2　Part A：缓存模拟器

2.1　数据结构与总体流程

框架已经完成命令行解析、缓存分配、trace 读取与结果输出，并约定：跳过 I；对 M 连续调用两次 access_cache；每次访存不跨块，因此可忽略 size。缓存按“组优先”排布：第 i 组占用从 cache[i*E] 开始的 E 个连续行。每行记录有效位、tag 和最近使用计数 last_used（越大越新）。

2.2　access_cache 的实现

一次访存分为“地址拆分 → 查找 → 命中更新 / 缺失替换”三步：

  1. 地址拆分。组索引取自块偏移之上的 s 位：set = (addr >> b) & ((1<<s)-1)；tag 取自更高位：tag = addr >> (b+s)。
  2. 查找。遍历该组 E 行：若有效且 tag 相同则命中；同时记录第一个无效行（free_line）与 last_used 最小的有效行（lru_line）。
  3. 更新。命中时 hits++，并把该行 last_used 置为 ++tick；缺失时 misses++，优先使用无效行，否则换出 LRU 行并 evictions++，随后写入 tag、置有效、刷新时间戳。
static void access_cache(uint64_t addr)
{
    size_t set;
    uint64_t tag;
    line_t *lines;
    int i, victim, found;

    /* 组索引：块偏移之上的 s 位 */
    if (s == 0)
        set = 0;
    else
        set = (size_t)((addr >> b) & ((((uint64_t)1) << s) - 1));

    /* tag：再往上的所有位；b+s==64 时已无 tag 位 */
    if (b + s >= 64)
        tag = 0;
    else
        tag = addr >> (b + s);

    lines = &cache[set * (size_t)E];

    found = -1;
    victim = -1;
    {
        int free_line = -1, lru_line = -1;
        for (i = 0; i < E; i++) {
            if (lines[i].valid) {
                if (lines[i].tag == tag)
                    found = i;
                if (lru_line < 0 ||
                    lines[i].last_used < lines[lru_line].last_used)
                    lru_line = i;          /* 最久未使用 */
            } else if (free_line < 0) {
                free_line = i;             /* 编号最小的无效行 */
            }
        }
        victim = (free_line >= 0) ? free_line : lru_line;
    }

    if (found >= 0) {                       /* 命中 */
        hits++;
        lines[found].last_used = ++tick;
        if (verbose) printf(" hit");
        return;
    }

    misses++;                               /* 缺失 */
    if (verbose) printf(" miss");
    if (lines[victim].valid) {              /* 换出有效行才算 eviction */
        evictions++;
        if (verbose) printf(" eviction");
    }
    lines[victim].valid = 1;
    lines[victim].tag = tag;
    lines[victim].last_used = ++tick;
}

2.3　边界与正确性要点

  • s == 0：只有一个组，单独分支把组索引固定为 0，避免 1<<0 的掩码语义混淆。
  • b + s == 64：地址 64 位、块偏移与组索引恰好占满，没有 tag 位；此时令 tag = 0，避免对 64 位整数左/右移 64 位（C 标准中为未定义行为）。
  • 无效行优先：组内有无效行时不发生替换，evictions 不增加；这直接对应题目“一次替换同时计为一次缺失，但不是所有缺失都是替换”。
  • LRU 计数：每次命中或调入都 ++tick，组内取最小者换出，天然处理“访问历史为空”的初始状态（所有行的 last_used 初值为 0，但无效行优先，因此不会误选）。
  • verbose 输出：只追加 " hit" / " miss" / " miss eviction"，不输出换行；M 的两次调用自然产生 " miss hit"，与参考程序逐字节一致。

3　Part B：矩阵转置

3.1　目标缓存分析

缓存参数为 s = 5, E = 1, b = 5：共 32 组、直接映射、块大小 32 字节，即每块存 8 个 int，总容量 1 KB。对 M 列的矩阵，元素 A[i][j] 的字节地址为 base + 4*(i*M + j)，所在行号为 (i·M + j)/8，组号为该行号模 32。

  • 32×32：行号 4i + j/8，每一行恰好 4 个 cache 块；行 i 与 i+8 映射到完全相同的组，同列方向存在 4 路冲突。
  • 64×64：行号 8i + j/8，每一行 8 个块；行 i 与 i+4 同组，A、B 的对角块还会互相冲突。
  • 61×67：行长 61 个 int（244 字节），不按行对齐，组映射随行号漂移，主要靠分块消除列方向的重复缺失。

朴素按行转置时，写 B[j][i] 沿列方向跨行，每写一个元素就可能换入一个只用一次的块，因此基线有 1184 次 miss。下面针对三种尺寸分别优化。

3.2　32×32：8×8 分块

把矩阵划成 8×8 子块。对每个子块，一次读入 A 的一整行（8 个 int 恰好一个 cache 块），放进 8 个寄存器，再按列写回 B：

for (i = 0; i < 32; i += 8)
  for (j = 0; j < 32; j += 8)
    for (k = 0; k < 8; k++) {
      a0 = A[i+k][j]; ... a7 = A[i+k][j+7];      /* 1 次读块，8 次使用 */
      B[j][i+k] = a0; ... B[j+7][i+k] = a7;      /* 写 B 的 8 行 */
    }

每个子块对 A 是 8 次读块（8 行）、对 B 是 8 次写块（8 行），共 16 次；16 个子块即 256 次，其余来自子块间的对角冲突，实测 288，优于满分线 300。

3.3　64×64：8×8 分块 + 4×4 象限重排

单纯 8×8 分块在 64×64 上约 4700 次 miss，原因有二：A 的 8 行只落在 4 个组上（行 i 与 i+4 冲突），且 A、B 的对角子块落在同一组，读 A 会反复踢掉 B 的暂存数据。为此把每个 8×8 子块再切成 4 个 4×4 象限：

  1. 上四行。对 k = i … i+3，一次读入 A[k][j..j+7] 的 8 个值。左上象限直接转置写入 B[j..j+3][k]；右上象限暂时寄存在 B 的右上区域 B[j..j+3][k+4]（该区域稍后才需要）。
  2. 左下与暂存交换。对 k = j … j+3，读 A[i+4..i+7][k]（左下象限），同时从 B 右上取回寄存值；把左下象限写入 B 的右上，把寄存值写入 B 的左下 B[k+4][i..i+3]。这一步是整段代码的关键：它让“A 右上 → B 左下”的搬运与“A 左下 → B 右上”的写入共用同一批 cache 行，避免了对角块的反复换入换出。
  3. 右下象限。对 k = i+4 … i+7 直接读 A[k][j+4..j+7] 写入 B[j+4..j+7][k]，此时两侧都不再被重复使用。
for (i = 0; i < 64; i += 8)
  for (j = 0; j < 64; j += 8) {
    for (k = i; k < i + 4; k++) {
      a0 = A[k][j]; ... a7 = A[k][j+7];
      B[j][k] = a0; ... B[j+3][k] = a3;
      B[j][k+4] = a4; ... B[j+3][k+4] = a7;     /* 暂存右上象限 */
    }
    for (k = j; k < j + 4; k++) {
      a0 = A[i+4][k]; ... a3 = A[i+7][k];        /* 左下 */
      a4 = B[k][i+4]; ... a7 = B[k][i+7];        /* 取回暂存 */
      B[k][i+4] = a0; ... B[k][i+7] = a3;        /* 左下 → 右上 */
      B[k+4][i] = a4; ... B[k+4][i+3] = a7;      /* 暂存 → 左下 */
    }
    for (k = i + 4; k < i + 8; k++) {
      a0 = A[k][j+4]; ... a3 = A[k][j+7];
      B[j+4][k] = a0; ... B[j+7][k] = a3;        /* 右下 */
    }
  }

局部变量为 8 个数据寄存器 a0…a7 加 3 个循环变量，满足“至多 12 个 int”的限制；A 全程只读。实测 1180 次 miss，优于满分线 1300。

3.4　61×67：64 行 × 16 列分块

该尺寸两个方向都不是 8 的倍数，且行长为 61，组映射没有整齐的周期。我先用边缘保护（k < N、l < M）保证正确性，再对分块参数做小规模扫描（8/12/16/20/24/32/40/56/64 行 × 8/12/16/20/24/32/48/61 列）。

分块 (行×列)8×816×1640×1656×1664×1664×2064×32
miss2119199318651864186219082556

最终取 64 行 × 16 列：16 列恰好是 A 的两条 cache 行，B 的写入集中在 16 行的窄列块；一次沿 64 行的高条带读 A，可以把 B 的列块在缓存中保留更久，从而摊薄列方向的重复缺失。实测 1862 次 miss，优于满分线 2000。

4　Part C：矩阵乘法

4.1　问题分析

计算 C = A × B，其中 A 为 N×M、B 为 M×N、C 为 N×N，评测尺寸为 32×32。三个 32×32 矩阵各 128 条 cache 行，而缓存只有 32 行，任何两个矩阵都无法同时整体驻留。朴素 i-j-k 写法沿列读 B，每个元素都要跨过整行，实测 35908 次 miss。

把循环改为分块后，关键是让每个被搬入缓存的行在换出前参与尽量多的乘加：一条 A 的行块（8 个 int）可与 8 个不同的 j 相乘，一条 B 的行块同样可服务 8 个 i。因此采用 8×8×8 三重分块。

4.2　实现：8×8×8 分块 + 8 个累加器

外层按 8×8 划分 C 的子块，内层再按 8 划分 k。对 C 子块中的每一行 ii，用 8 个寄存器 a0…a7 累加这一行的 8 个元素：

  • 当 k0 == 0 时把累加器清零；否则从 C 读回上一次 k 分块的中间结果（C 的初始内容是垃圾值，不能直接使用）。
  • 对 kk = k0 … k0+7：读一次 A[ii][kk]，再读 B 的一整行块 B[kk][j0..j0+7]，一条 A 元素服务 8 个乘加，一条 B 行块也服务 8 个乘加。
  • 一个 k 分块结束后，把 8 个累加器写回 C[ii][j0..j0+7]（一条 cache 行）。
for (i0 = 0; i0 < N; i0 += 8)
  for (j0 = 0; j0 < N; j0 += 8)
    for (k0 = 0; k0 < M; k0 += 8)
      for (ii = i0; ii < i0 + 8 && ii < N; ii++) {
        if (k0 == 0) a0 = a1 = ... = a7 = 0;
        else { a0 = C[ii][j0]; ... a7 = C[ii][j0+7]; }   /* 读回部分和 */
        for (kk = k0; kk < k0 + 8 && kk < M; kk++) {
          t = A[ii][kk];
          a0 += t*B[kk][j0]; ... a7 += t*B[kk][j0+7];
        }
        C[ii][j0] = a0; ... C[ii][j0+7] = a7;            /* 写回 */
      }

为什么这样能减少冲突。在固定的 k0 下，B 的 8 条行块 B[kk][j0..j0+7] 落在 8 个互不相同的组（组号相差 4），恰好能被 32 组缓存容纳；处理 8 个 ii 时它们一直驻留，每条 B 行块被复用 8 次。A 的当前行块也在同一条 kk 循环中被复用 8 次。C 的每一行块在 4 个 k 分块中各读写一次，但相邻访问命中同一条缓存行。

局部变量为 8 个累加器 + 1 个临时 t + 5 个循环变量，满足“至多 16 个 int”的限制；A、B 只读，C 的每个元素都被写入（k0 == 0 时清零后累加，最后一个 k 分块写回最终值）。

5　Bonus：缓存逆向

未知缓存的地址为 32 位，参数范围：b ∈ [3,7]、s ∈ [1,9]、E ∈ {1,2,3,4,5,6,8,12,16}，替换策略为 LRU / FIFO / RANDOM 之一，写缺失可能写分配或不写分配。只能通过 cache_load、cache_store、cache_flush 探测。下面给出每一步的探测方法、正确性证明与代价。

5.1　块偏移位数 b

清空缓存后读地址 0，把块 0 调入；随后依次读 1, 2, 4, …, 2^t。只要 2^t < 2^b，该地址仍落在块 0 内，必然命中；第一次越过块边界（2^t = 2^b）时发生强制缺失，于是 第一个缺失的 2 的幂次偏移量就是 b。由于 b ∈ [3,7]，最多探测 8 次。

5.2　容量乘积 P = E·2s

设一组“探测族”为块编号 i·2^t（i = 0,1,…,N-1，地址再左移 b 位）。先把前 N 个块全部读入，再按原顺序重读一遍，若重读出现任何缺失就称该 N 为“坏”的。

块 i·2^t 的组号为 (i·2^t) mod 2^s。该族只落在 2^s / gcd(2^t, 2^s) 个组上，每组平均分到 N·gcd(2^t,2^s)/2^s 个块。只有当某组超过 E 个块时才会换出，故第一次出现缺失的 N 为

Nmin(t) = E · 2s − min(t,s) + 1.

取 t = 0（连续块），得 Nmin(0) = E·2^s + 1 = P + 1，因此用二分查找出最小的“坏” N 后，P = N − 1。该判据与替换策略无关：只要某组超过容量，必有块被换出，重读时必然缺失；未超过容量时全部驻留，重读全部命中。

5.3　组索引位数 s 与相联度 E

对候选 t，取 N = ⌊P/2^t⌋ + 1 做一次上述探测：

  • 若 t ≤ s，则 P/2^t = E·2^(s−t) 为整数，N = Nmin(t)，恰好触发换出，探测结果为“坏”；
  • 若 t > s，则 N = ⌊E/2^(t−s)⌋ + 1 ≤ E（因 t−s ≥ 1 且 E ≥ 1），而 Nmin(t) = E+1，所以 N ≤ E < Nmin(t)，探测结果为“好”。

于是命题“t ≤ s”关于 t 单调（前真后假）。在 t ∈ [1,10] 上二分，最大的真值 t 就是 s；再由 E = P / 2^s 得到相联度，并一定落在合法集合中。上述推导对任意 b,s,E 与任意替换策略成立，因为它只依赖“组容量为 E”这一事实。

5.4　替换策略

取同一组内的 E 个块 0, 2^s, 2·2^s, …, (E−1)·2^s（地址再左移 b 位），依次读入填满该组；再读一次块 0（命中）；最后调入一个新块（块 E·2^s，仍在同一组），观察块 0 是否还在：

  • LRU：对块 0 的命中把它变成“最近使用”，因此新块会换出块 1，块 0 保留；
  • FIFO：命中不改变调入顺序，块 0 仍是最早调入者，被新块换出；
  • RANDOM：在 E 行中均匀随机换出，块 0 以 1/E 的概率被换出，不同试验结果不同。

重复 300 次独立试验（每次先 cache_flush）：LRU 恒为 300 次命中，FIFO 恒为 0 次命中；RANDOM 出现两种结果之一是极小概率事件，其上界为 max((1/E)^300, (1−1/E)^300) ≤ (15/16)^300 ≈ 4×10−9（E ≤ 16）。因此“全命中 → LRU、零命中 → FIFO、混合 → RANDOM”的判定在允许范围内几乎必然正确。E = 1 时策略不计分，直接报告 LRU。

E = 4 时 LRU 与 FIFO 的分歧示例。设某组的四个块按地址升序记为 A、B、C、D，新块记为 E，访问序列： A, B, C, D, A, E, A。 前四次 A,B,C,D 填满该组；第五次访问 A 命中。 此时 LRU 的次序变为 B, C, D, A，FIFO 的调入次序仍为 A, B, C, D（命中不影响顺序）。 第六次访问 E 时，两者开始分歧：LRU 换出 B，FIFO 换出 A。 第七次再访问 A：LRU 命中（A 仍在），FIFO 缺失（A 已被换出）。 对应到实际地址，取 A = 0、B = 2s+b、C = 2·2s+b、D = 3·2s+b、E = 4·2s+b，它们都落在 0 号组。

5.5　写分配

清空缓存后，先对某块执行一次 cache_store（必然写缺失），再 cache_load 同一块：若写缺失分配了该块，则读命中（write_allocate = 1）；否则缓存不变，读缺失（write_allocate = 0）。只需两次探测，且与替换策略和几何参数无关。

5.6　结果与健壮性

5.7　探测代价

最大的一次探测族长度是 P+1 ≤ 16·2^9+1 = 8193。二分查找 P 约十几次探测族，每次至多 2N 次访存；求 s 至多 4 次同类探测；策略判定为 300×(E+3) ≤ 5700 次。总探测次数约 104～105 量级，实测最大 75271 次，留有约 13 倍余量。

6　总结

本实验从三个角度实践了 CS:APP 第 6 章的核心思想：

  1. Part A 用精确的地址拆分与 LRU 状态维护，复现了参考模拟器的全部计数与 verbose 输出，并正确处理了 s=0、b+s=64 等边界。
  2. Part B 通过计算每个矩阵元素落入的组，针对 32×32、64×64、61×67 分别设计了 8×8 分块、4×4 象限重排与 64×16 长条分块，miss 数分别为 288、1180、1862，均达到满分线。
  3. Part C 用 8×8×8 三重分块和 8 个寄存器累加器，让每条 A/B 缓存行在被换出前参与 8 次乘加，把 35908 次 miss 降到 2656。
  4. Bonus 把缓存逆向转化为几个可证明的容量判据：用“首次换出的探测族长度”求出 E·2^s，再用步长 2^t 的阈值把乘积拆成 s 与 E；用命中是否改变淘汰次序区分 LRU/FIFO，用重复试验识别 RANDOM；用“写缺失后重读”判定写分配。

所有源码均满足题目约束：无编译告警；Part B 每个函数至多 12 个 int 局部变量、Part C 至多 16 个；未使用全局变量、malloc、递归或辅助函数；转置不修改 A，乘法不修改 A、B 且写满 C 的每个元素。
